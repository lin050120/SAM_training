# 画像グループ分け（Train / Val の手動分割）

UI：「画像グループ分け」タブ。コード：`ui/dataset_grouping_page.py` +
`core/manual_dataset_split.py`。テスト：`tests/test_manual_dataset_split.py`。

## 何を解決するか

自動分割（`docs/DATASET_AUTO_SPLIT_JA.md`）は比率に従ってランダムに切り分けるだけで、
どの写真が同じ本棚を撮ったものかを知りません。同一シーンの写真が train と val の
両側に分かれると、検証指標は楽観的に偏ります——モデルが val で見るのは、学習時に
ほぼ見た画だからです。このページでは画像単位で所属を決め、各画像に**シーングループ**
のラベルを付けられます。

**元データは決して変更されません**。エクスポートは常に新しいディレクトリに書き出します。

## 操作の流れ

1. **読み込み**：サーバーパスを 1 行に 1 つ入力します。分割して追加できます。
   - 標準データセットディレクトリを指定した場合、`train/val/test` 配下の
     `annotations.json` のみを読み込み、隣接するバックアップディレクトリ
     （例：`test.pre_0725_merge_20260725/`）は無視します。
   - それ以外のディレクトリでは COCO を再帰的に探索します。単一の COCO ファイルを
     直接指定することもできます。
   - すでに `train/val/test` サブディレクトリにある画像は**元のグループを引き継ぎ**、
     **test はロックされます**。以後 train/val へ移動できず、リスト復元でも身分を
     変更できません。
2. **閲覧**：1 ページ 24 枚。アノテーション付きでプレビューします（ポリゴンは輪郭、
   RLE は外接矩形）。ファイル名 / パス / シーングループで絞り込めます。
3. **割り当て**：このページの画像を選択 → シーングループ名を任意入力 →
   train / val / 未割り当て を選択 → 適用。
   **絞り込みやページ移動で選択は解除されます**。ページをまたぐ前に、現在のページを
   適用してください。
4. **エクスポート**：**未作成の**新しいディレクトリを指定して実行します。画像はコピーされ
   `im_%06d` にリネームされ、COCO の image/annotation/category ID はすべて振り直され、
   同名カテゴリはバッチをまたいで同一 ID に統合されます。

エクスポートしても学習パスは**自動で切り替わらず**、認可も**自動では付与されません**。
正式学習に使うには「データセット登録」ページで人手レビューと登録が必要です
（`docs/DATASET_REGISTRATION_UI_JA.md` 参照）。

## 完全性の保証

- **画像内容の重複**：sha256 で判定し、読み込み時に重複を検出すると即エラー。
  同一画像がグループをまたいで漏れることを防ぎます。
- **画像と COCO の不一致**：読み込み時に `width/height` と実画像サイズを照合します。
- **読み込み後の変更**：エクスポート前に各ソース COCO の sha256 を再検証し、
  コピー後は画像ごとに sha256 を検証します。
- **上書きしない**：出力ディレクトリは未作成であること、かつ入力 COCO ディレクトリの
  内部であってはなりません。
- **原子性**：まず一時ディレクトリに書き、最後に `os.replace` でまとめて配置します。
  途中で失敗しても中途半端な成果物は残りません。

## シーングループは警告であって強制ではない

`group` フィールドは、同一シーングループが train と val の両方に現れることを
**阻止しません**。既定値がソースディレクトリ名（標準データセットを読み込むと
グループ名は `train`/`val`/`test`）であるため、既定状態でまたがるのは正常であり、
強制的にブロックすると通常の利用ができなくなるからです。

そのため**ブロックではなく警告**という方針を採っています：
- グループ集計欄に `⚠ 同时出现在 Train 和 Val 的场景组：...` を常時表示
- エクスポート結果でも再度提示

この警告が出たら自分で判断してください。グループ名が既定のディレクトリ名のままなら
無視して構いません。自分で命名したシーングループ（例：`本棚A_上段`）なら、実際に
同一シーンの漏れがあるということなので、片側に寄せるべきです。

プログラムから確認する場合は `core.manual_dataset_split.split_spanning_groups(state)`
を使います。`{グループ名: [出現した split]}` を返します。

## 固定リストと再現

エクスポート先の `manual_split.json` に、各画像の key・sha256・split・group が
記録されます。「リストを復元」で同じソースを当時の分割に戻せます。ただし
**まったく同じソースを先に読み込んでいること**、画像とアノテーションが変更されて
いないこと（sha256 が検証されます）が前提です。

復元は**画像の内容（sha256）で照合**し、パスは見ません。そのためソースデータを別の
ディレクトリや別のマシンへ移した後でも、古いリストがそのまま使えます。リスト内の `key`
は `<COCO の絶対パス>::<image_id>` の形式ですが、これはそのセッション限りのハンドルで
あり、復元時の照合には使いません。ファイル形式は変わっていないので、以前に
エクスポートしたリストも新しい規則で復元できます。

以下は引き続き拒否されます（意図的な完全性チェックです）：
- 読み込んだ画像の集合がリストと一致しない（「請加載與名單完全相同的源數據」）
- アノテーションの内容が変わっている（`source_sha256` の不一致）
- リストが画像の Test 身分を変更しようとしている

## 既知の挙動

- 読み込み後に画像ファイルが移動・削除された場合、ギャラリーはその位置に
  「読み込み失敗」のプレースホルダを表示し、ページ全体は壊れません。ただしレコードは
  状態に残るため、エクスポート時に sha256 検証で失敗します。
- 絞り込みボックスは **Enter で適用**されます（「更新 / ページ移動」ボタンでも可）。
  再描画のたびにアノテーション付きサムネイルを 24 枚生成するため、1 文字ごとに発火すると
  重くなるからです。即時反映されるのは「表示するグループ」ドロップダウンのみです。
